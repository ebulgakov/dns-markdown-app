# Expo HAS CHANGED

Read the exact versioned docs at https://docs.expo.dev/versions/v57.0.0/ before writing any code.

# React Native / Expo rules

- Before adding any RN library — check New Architecture compatibility.
- Install dependencies via `npx expo install`, not `npm install`.
- Use `expo-router` for navigation, not `react-navigation` directly.
- CNG (Continuous Native Generation): don't touch `ios/` or `android/` by hand — they're generated by `expo prebuild`, manual edits get lost.

# Project structure

FSD target shape: `shared → entities → features → widgets`.

- `src/app/` — expo-router file-based routes.
- `src/features/` — feature slices; each has `index.ts` (public API) + `ui/`.
- `src/entities/` — reusable domain models (e.g. product, user) shared across features. *(not created yet — add when a second feature needs the same domain data)*
- `src/widgets/` — app-shell composition (navbar/tab-bar chrome) used from `app/`. *(not created yet)*
- `src/shared/` — cross-feature infra with no business logic (providers, notifications).
- `src/theme/` — theme source of truth (`colors.ts`).
- `src/lib/` — small reusable helpers (e.g. `cn.ts`, `use-color-scheme.tsx`).

# File naming

Files under `src/` and `app/` use kebab-case — no uppercase letters — for every file type, including components: `src/features/sign-in/ui/sign-in.tsx`, `src/shared/providers/expo-clerk-provider.tsx`. Exported identifiers keep normal JS/React convention: PascalCase for components, camelCase for hooks/functions.

# Component & styling conventions

- Style with NativeWind `className` + the `cn()` helper (`src/lib/cn.ts`), not inline `style={{}}` objects.
- For variant-based styling (status/enum-driven visual differences), use `cva` (`class-variance-authority`, already a dependency) instead of ad hoc conditional styles.
